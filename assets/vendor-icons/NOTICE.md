# Vendor icons — provenance and the position taken

Marks belonging to vendors that are **not** AWS. They live here and not in
`assets/aws-icons/` for one reason: that directory's notice records a position
taken about *AWS's* terms, and a mark governed by someone else's terms does not
belong under it.

## GitHub

`github.svg` is the `mark-github` icon from **Octicons**, GitHub's own icon set,
published by GitHub at <https://github.com/primer/octicons> under the **MIT
licence**. It is unmodified apart from the `<title>` and the `fill="currentColor"`
the set already ships with.

That is a real licence, granted in writing by the mark's owner, for the icon
itself. It is a firmer footing than the AWS icons next door stand on — those are
used under a position taken *in the absence of a no*, which their notice says out
loud.

GitHub's separate logo guidance (<https://github.com/logos>) covers the *brand*
rather than the icon set: it permits using the mark to refer to GitHub, and asks
that it not be modified or used to imply endorsement. Both are satisfied here —
the card it sits on says what GitHub is to this project and claims nothing else.

## The rule, so it is not re-derived wrongly

    a vendor's own mark   used, under that vendor's own terms, recorded here
    never AWS's mark      for something that is not an AWS service - that is
                          AWS's trademark guidance and it stands
    a project glyph       only where no vendor mark exists. `WWW` for a browser
                          is right: a browser has no vendor

This file exists because the absence of a rule was once read as a prohibition.
Nothing in `assets/aws-icons/NOTICE.md` ever forbade a non-AWS vendor's own
logo; a session inferred it, and the GitHub card carried the letters `CI` for
longer than it should have.
