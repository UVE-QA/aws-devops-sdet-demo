What happens, in the order it happens

Permanent — no destroy workflow touches these

Five Terraform state levels applied once, by hand, under a human SSO session. The exhibit cannot be destroyed by the thing it exhibits, so anything that has to survive a teardown — including the artifact that proves the teardown worked — lives above the environments.

bootstrap S3 state bucket bootstrap-oidc OIDC provider + one deploy role per environment shared-ecr the registry prod promotes from dns delegated zone + ALB certificate public-site this page: S3 + CloudFront + OAC

Per cycle — created and destroyed every time

Every step below runs in GitHub Actions under a short-lived OIDC token. There are no static AWS keys anywhere in this project, and no human runs an AWS command during a cycle.

1 build image → shared ECR → 2 apply VPC, ALB, ECS Fargate, RDS → 3 migrate + seed as an ECS task → 4 gate API contract, smoke, regression, DB assertion → 5 approve a human, in the prod environment → 6 promote the tested digest, not a rebuild → 7 destroy both, verified against the AWS CLI

Suites are bound to directories, so where a test lives decides where it runs: the destructive ones cannot reach prod, and a spec that belongs to no suite fails the build rather than being silently reported by nothing.
